# SMTP 오류를 일시·영구·시스템 세 종류로 분류하고, 재시도는 backoff와 만료 시각으로 제어한다

## 상태

승인됨 (2026-11-23)

유지한 결정(5·6·8)과 ADR-0007이 이어받은 규칙은 1단계에서 구현했다. 구현 상태와 확정 내용은 ADR-0007의 "구현 중 확정"을 따른다.
검증은 로컬 SMTP 서버와 PostgreSQL 대상 테스트까지다. 실제 Gmail 서버 대상 검증은 하지 않았다.

ADR-0007 승인(2026-11-23)으로 결정 1~4와 7을 ADR-0007이 대체했다.
원문은 유지하고 각 결정에 "대체됨" 표기를 붙인다.
결정 5(backoff), 결정 6(만료 처리), 결정 8(시도 기록)은 유지한다.

## 배경

요구사항 RQ-008~010이 재시도 설정, 오류 분류, 재시도 중단 조건을 정한다.
ADR-0002는 `RETRY_WAIT`·`FAILED`·`EXPIRED` 전이를 정했지만, 어떤 오류가 어느 전이로 가는지는 정하지 않았다.

Google 문서에서 확인한 사실이다. 출처는 문서 끝에 있다.

- SMTP 응답의 `5xx`라도 시간이 지나면 풀리는 한도 초과가 있다.
  - `550 5.4.5`는 사용자별 일일 발송 한도 초과다.
  - SMTP relay에는 `550 5.4.5`(사용자별 일일 relay 한도)와 `550 5.7.1`(고객 전체 일일 relay 한도)이 있다.
- 일시적 속도 제한은 `4xx`로 응답한다.
  - 예: `421 4.7.0`, `421 4.4.5`, `450 4.2.1`(relay 순간 한도).
  - Google은 이 경우 exponential backoff를 구현하도록 안내한다.
- 한도는 고정 시각 초기화가 아니라 24시간 rolling 기준이다.
- 인증 실패는 `535` 계열로 응답한다. 정확한 보조 코드는 구현 시 Google 표로 확인한다.
- 한도 수치(예: Workspace SMTP 일 2,000통, relay 사용자당 일 10,000통, relay 한 SMTP 트랜잭션당 수신자 100명)는 문서 갱신으로 바뀔 수 있다. 이 ADR은 수치를 고정하지 않는다.

## 결정

1. **SMTP 결과를 세 종류로 분류한다.** 대체됨: ADR-0007 결정 1~3. 분류 축이 SMTP 단계로 바뀌고 `SYSTEM`은 계정 상태 오류로 흡수됐다.

| 분류        | 의미                                  | 작업 처리                                                         |
| ----------- | ------------------------------------- | ----------------------------------------------------------------- |
| `TRANSIENT` | 시간이 지나면 성공할 수 있는 오류     | `RETRY_WAIT`                                                      |
| `PERMANENT` | 같은 요청을 다시 보내도 실패하는 오류 | 즉시 `FAILED`                                                     |
| `SYSTEM`    | Mailo 구성·인증 문제. 작업 탓이 아님  | 작업은 `RETRY_WAIT` 유지. 전역 발송 일시 중지 조건에 반영한다     |

2. **기본 분류 규칙은 응답 코드 계열을 따른다.** 대체됨: ADR-0007 결정 3. 코드 계열 규칙은 메시지 단계(`MAIL FROM`·`RCPT`·`DATA`)에만 적용한다. 연결·TLS·타임아웃은 계정 상태 오류다.
   - `4xx`는 `TRANSIENT`다.
   - `5xx`는 `PERMANENT`다.
   - 연결 거부, DNS 실패, TLS 오류, 타임아웃은 `TRANSIENT`다.
3. **기본 규칙에 대한 예외는 코드의 매핑 표로 관리한다.** 대체됨: ADR-0007 결정 3·4. 매핑 표는 메시지 단계에만 쓰고, 한도 초과는 계정 상태 오류로 분류한다.
   - 매핑 키는 SMTP 응답 코드와 enhanced status code 조합이다.
   - `5xx`여도 한도 초과인 응답은 `TRANSIENT`로 분류한다. 예: `550 5.4.5`.
   - 매핑에는 항목별 최소 대기 시간을 지정할 수 있다. 일일 한도 초과는 24시간 rolling이므로 일반 backoff보다 길게 둘 수 있다.
   - 매핑 표의 내용은 구현 시 Google 오류 표로 확정한다.
4. **인증 실패(`535` 계열)와 구성 오류는 `SYSTEM`으로 분류한다.** 대체됨: ADR-0007 결정 2·5. 계정 상태 오류로 분류하고 전역 차단기(DB 행 하나)로 처리한다. 차단기 상태는 헬스 응답(RQ-031)과 로그에 드러낸다(ADR-0007 결정 5).
   - 인증 정보를 고칠 때까지 모든 작업이 같은 오류로 실패한다.
   - 작업을 `FAILED`로 만들지 않는다.
   - `SYSTEM` 시도는 최대 시도 횟수에 포함하지 않는다. 만료 시각은 계속 적용한다.
   - 연속 `SYSTEM` 오류가 임계값에 이르면 Worker가 작업 점유를 중지한다.
   - 중지 상태는 로그와 헬스 응답에 드러낸다.
5. **재시도 간격 기본 정책은 jitter를 더한 exponential backoff다.**
   - 다음 시도 시각은 `now + min(상한, 기준 × 2^(n-1))`에 jitter를 더해 계산한다.
   - 고정 간격 정책을 선택할 수 있다.
   - 기준 간격, 상한, 최대 시도 횟수의 기본값은 설정으로 받는다. 기본값은 RQ-008에 정했다(추정값). 기준 1분, 배수 2, 상한 1시간, jitter ±20%, 최대 8회, 만료 TTL 24시간이다.
6. **만료 시각이 다음 시도보다 앞서면 대기하지 않고 `EXPIRED`로 만든다.**
   - 계산한 `next_attempt_at`이 `expires_at`보다 뒤이면 해당 시점에 즉시 `EXPIRED`로 전이한다.
   - 진행 중인 시도는 중단하지 않는다(ADR-0002 결정 7).
7. **시도 타임아웃은 `TRANSIENT`이며 수락 여부가 불명이다.** 대체됨(일부): ADR-0007 결정 3. `DATA` 단계의 타임아웃·연결 끊김만 `TRANSIENT`다. 그 앞 단계의 타임아웃은 계정 상태 오류다. 수락 여부 불명과 `lease_until` 관련 문장은 유지한다.
   - 서버가 수락했는데 응답만 늦은 경우 재시도가 중복 발송이 된다(RQ-013).
   - ADR-0002의 `lease_until`은 연결·전송 타임아웃 합보다 길어야 한다.
8. **각 시도의 오류 정보를 `mail_attempts`에 기록한다.**
   - 기록 항목: 분류, SMTP 응답 코드, enhanced status code, 응답 텍스트, 시작·종료 시각.
   - 본문은 기록하지 않는다.

## 검토한 대안

| 대안                                | 채택하지 않은 이유                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| 코드 계열만으로 분류(`4xx`/`5xx`)   | 한도 초과 `550 5.4.5`가 영구 실패로 처리돼 복구 가능한 메일을 잃는다                            |
| 인증 실패를 `PERMANENT`로 분류      | 인증 정보 오류 하나로 큐의 모든 작업이 `FAILED`가 된다                                          |
| 인증 실패를 일반 `TRANSIENT`로 분류 | 작업마다 시도 횟수가 소모되고, 잘못된 인증으로 반복 접속해 계정이 잠길 수 있다(추정이며 미검증) |

## 결과

- 일시적 한도 초과로 정상 메일이 `FAILED`가 되는 경우를 줄인다.
- 매핑 표를 유지해야 한다. Google이 응답 코드를 바꾸면 표를 갱신해야 한다.
- 대체됨: ADR-0007(계정 상태 오류). `SYSTEM` 오류가 길어지면 만료 시각이 지난 작업이 `EXPIRED`로 쌓인다. ADR-0007의 차단기도 같은 한계가 있다.
- 유지한 결정 5(backoff)·6(만료)·8(시도 기록)은 단위·통합 테스트로 확인했다. 실제 Gmail 서버 대상 동작은 확인하지 않았다.

## 미확정

현재 상태다.

- 결정됨: 기준 간격·상한·최대 시도 횟수·jitter의 기본값은 RQ-008에 정했다(추정값). 기준 1분, 배수 2, 상한 1시간, jitter ±20%, 최대 8회, 만료 TTL 24시간.
- 결정됨: `SYSTEM` 연속 오류 임계값과 중지 해제 조건은 ADR-0007 결정 5(차단기)가 대체한다.
- 결정됨: 한도 초과 응답별 대기 시간은 ADR-0007 결정 4가 정했다. 일일 한도는 open 1시간 뒤 half_open, 순간 한도는 open 5분에서 시작해 대표 실패마다 2배로 늘며 상한은 30분이다(추정값).
- 결정됨: 발송 속도 제어는 호출처별 24시간 rolling 할당으로 둔다(ADR-0007 결정 10, RQ-032). 기본값은 무제한이다. 구현됨(2026-11-23, ADR-0007 구현 중 확정 7). 한도에 닿기 전 계정 전체 속도 제어는 정하지 않았다.
- 결정됨: 일부 수신자만 거부되는 경우는 ADR-0007 결정 7이 정했다. 일부 수락이면 `SENT`로 처리하고, 전원 거부이면 하나라도 `4xx`일 때 `TRANSIENT`, 모두 `5xx`일 때 `PERMANENT`다.
- 결정됨: 응답 텍스트에 수신자 주소가 포함될 때의 마스킹은 ADR-0007 "구현 중 확정" 5가 정했다. 이메일 주소 형태를 `[address]`로 바꾸고 500자로 자른다. 구현 중 확정이다.
