## 진행 상태 요약 (2026-11-24, ADR-0015 승인 반영)

상태 어휘는 `미착수`·`진행 중`·`검증 완료`·`보류`다(`mail-sending.md`의 "용어와 진행 상태"). 이 표는 RQ별 상태를 요약한 것이고 기준은 각 RQ의 수용 조건 체크다. 검증 완료 38건, 진행 중 30건(RQ-060~063, RQ-064·065, RQ-067~069 포함), 미착수 6건(RQ-066, 9단계 묶음 C. RQ-070~074, 10단계), 보류 0건이다. 4단계 발송 우선순위는 RQ-033~037이 검증 완료이고 RQ-038이 진행 중이다. 5단계 요청별 만료 시간(RQ-039)은 문서 조건이 검토로만 확인돼 진행 중이다. 6단계 묶음 A(ADR-0011 결정 4의 호출처 취소)는 RQ-040이 검증 완료이고 배포 호환성(RQ-041)은 롤링 배포·롤백 실행과 저장소 밖 호출처 확인이 남아 진행 중이다. 6단계 묶음 B(토큰 분리, 발송 정지, 감사, `/ops` REST, 관리 취소)는 RQ-042·044가 검증 완료이고 발송 정지(RQ-043)는 롤링 배포·롤백 실행과 다중 인스턴스 측정이 남아 진행 중이다. 6단계 묶음 C는 수신 도메인 허용 목록(RQ-046)과 운영 CLI(RQ-047)가 검증 완료이고 이벤트 피드 공백 감지(RQ-045)는 롤링 배포·롤백 실행과 보존 삭제·조회의 동시 실행이 남아 진행 중이다. 6단계 묶음 D 결과 불명 표시(RQ-048)는 검증 완료다. ADR-0011의 결정 1~10은 모두 구현했고(구현 완료, 미검증 항목 있음) 호출처 단위 일괄 취소는 ADR상 범위 밖이다. 8단계 관측성(ADR-0012)은 `/metrics` 인증·응답 형식(RQ-049)과 전역 gauge·DB 수집(RQ-051)이 운영 크기·다중 인스턴스 측정과 실제 Prometheus 운영 확인이 남아 진행 중이고, 이름·라벨·시크릿 규칙(RQ-050)과 인스턴스 counter·gauge(RQ-052)는 검증 완료다. 마이그레이션이 없고 `/health/ready` 계약은 그대로다. 7단계 다중 SMTP 계정(ADR-0013)은 묶음 A(계정 모델: 계정 파일 로더 RQ-053, 호출처 `accountId`·작업 계정 고정·`0010`·`0011` RQ-054, 계정별 전송·발신 주소 허용 집합 RQ-055, 배포 호환성·시크릿 비노출 RQ-056)를 구현했다. 네 RQ 모두 롤링 배포·롤백 실행, 읽기 전용 컨테이너의 계정 파일 마운트, 실제 Gmail·Workspace 계정 둘 이상이 남아 진행 중이다. 묶음 B(계정 단위 점유와 차단기·정지 격리 RQ-057, 계정 24시간 할당과 슬롯 배분 RQ-058, 계정 인덱스 `0012`~`0016`과 건수 쿼리 RQ-059)를 구현했다. 세 RQ 모두 롤링 배포·롤백 실행, 동시 쓰기·다중 인스턴스 부하 확인, 실제 Gmail·Workspace 계정이 남아 진행 중이다. 비`default` 계정의 기동 거부는 없앴다. 묶음 C(운영 표면)·D(호출처 동시 상한)는 구현 전이다. 9단계 호출처 도구와 문서(ADR-0014)는 묶음 B를 구현했다. 적합성 벡터와 서버 고정(RQ-064)·벡터 키의 production 거부(RQ-065)는 호출처 라이브러리와의 상호 운용, 벡터 키로 컨테이너 실제 기동, push protection, 문서 검토로만 확인한 항목이 남아 진행 중이다. 묶음 A(키 사고 대응 RQ-067, DB 유지보수 RQ-068, 레지스트리 변경 반영 RQ-069)는 문서를 작성했고 코드 변경이 없다. 자동 검증이 없어 체크하지 않은 항목(문서 검토)이 남아 진행 중이다. RQ-068의 측정 기록·링크 검사는 수동 확인이라 체크하지 않았다. 묶음 C(Java 샘플 연동, 선택, RQ-066)는 구현 전이다. 10단계 개인정보 최소화와 결과 불명 정책(ADR-0015)은 2026-11-24에 승인됐고 RQ-070~074는 모두 미착수다. 묶음 A(보존 현황 문서, RQ-070)와 B(종결 때 비움, RQ-071)를 먼저 구현한다.

## 전체 미검증 목록

- 다중 SMTP 계정 묶음 C(RQ-060~063, ADR-0013): 저장소 밖 호출처가 `circuitBreaker`의 계정별 의미와 `sendPaused.scope`의 새 값 `account`를 처리하는지, 롤링 배포 중 구·신 혼용(구버전은 계정 정지를 읽지 않고 `circuitBreaker`가 `default` 값), 계정 20개 규모의 `/metrics` 시리즈 수와 스크레이프 쿼리 비용, 실제 Prometheus의 알림 규칙 평가, 읽기 전용 컨테이너에서 새 CLI 명령 실행.
- 다중 SMTP 계정 묶음 A·B(RQ-053~059, ADR-0013): 롤링 배포·롤백 실행(구버전은 `accountId`를 거부해 기동하지 못한다는 점과 컬럼을 무시한다는 점은 코드 읽기 결과), `0010`·`0011`의 `ACCESS EXCLUSIVE` 잠금 대기(ADR-0013 측정은 150만 행 단일 실행), 읽기 전용 루트 컨테이너의 계정 파일 마운트·`_FILE` 비밀 읽기, 실제 Gmail·Workspace 계정 둘 이상(계정별 한도, 앱 비밀번호 복수 발급, send-as 별칭의 `From`), `default`가 아닌 계정의 운영은 묶음 B에서 통합 테스트로 확인했다. 묶음 B(RQ-057~059): 롤링 배포 중 구·신 혼용과 레거시 인덱스(`0015`·`0016`) 삭제 뒤 구버전 점유 성능(ADR-0013 M8은 한 쿼리 측정), `CREATE`·`DROP INDEX CONCURRENTLY`의 동시 쓰기 부하 시간, 다중 인스턴스(4개 이상) 동시 부하의 poll 비용·풀 점유·계정 advisory lock 경합, 운영 크기·오래된 통계의 계획 안정성, 대표 작업 쿼리의 대량 대기 비용, 실제 Gmail·Workspace 계정의 한도·동시 연결.
- `/metrics`(RQ-049~052, ADR-0012): 운영 크기(수백만 행)·다중 인스턴스·Prometheus 복제본 여러 개의 동시 스크레이프에서 쿼리 비용과 풀 점유, 롤링 배포 중 구·신 혼용(구버전은 `/metrics`가 404라는 점은 코드 읽기 결과)과 롤백, 알림 규칙의 발화 조건과 임계값(부하에서 확인하지 않았다), 실제 Gmail 응답의 `stage`·`reason` 분포, 장시간 부하의 counter 정확도. 실제 Prometheus 스크레이프·`promtool check metrics`·`check rules`는 일회성으로 확인했다.
- 결과 불명 표시(RQ-048, ADR-0011 결정 5): 실제 Gmail·Workspace에서 `true`가 되는 응답 경로, 서버가 응답했지만 Mailo가 받지 못한 경우, 운영 크기에서 `EXISTS`·일괄 조회 비용, 저장소 밖 호출처가 새 필드를 무시하는지(Java 샘플은 확인함).
- 이벤트 피드 공백 감지·수신 도메인 허용 목록·CLI(RQ-045~047, ADR-0011 결정 7·8·9): 롤링 배포 중 구·신 인스턴스 혼용과 롤백 실행(구버전이 지운 이벤트가 표지에 오르지 않고 구버전이 새 레지스트리 필드를 거부한다는 점은 코드 읽기 결과), 보존 삭제와 `GET /events`의 동시 실행(조회 순서의 오탐 방향 추론), 실제 30일 경과, 운영 크기·다중 인스턴스에서 삭제 표지 갱신 비용, `docker compose exec`로의 CLI 실행, 저장소 밖 호출처가 `Mailo-Cursor-Gap` 헤더와 410을 처리하는지.

- 작업 취소(RQ-040·041, ADR-0011 결정 4·10): 롤링 배포 중 구·신 인스턴스 혼용과 롤백 실행, 대용량 테이블·쓰기 부하 중 `0006`·`0007`의 `ACCESS EXCLUSIVE` 잠금 대기, 이 저장소 밖 호출처가 모르는 값 규칙을 지키는지. 구버전 인스턴스의 `CANCELED` 처리는 코드 읽기 결과다. ADR-0011의 나머지 결정(CLI, 수신 도메인 허용 목록, 피드 공백 감지, 일괄 취소, `outcomeUncertain`)은 구현 전이다.
- 운영 토큰·발송 정지(RQ-042~044, ADR-0011 결정 1·2·3·6·7): 롤링 배포 중 구·신 인스턴스 혼용과 롤백 실행(구버전은 정지를 읽지 않는다는 점은 코드 읽기 결과), 다중 인스턴스에서 정지 명령 직후 점유를 마친 작업 수(추정 상한은 인스턴스 수 × 동시 전송 수), 정지 해제 직후의 SMTP 계정 한도 반응, 정지한 호출처가 큰 대기를 가질 때 운영 크기의 점유 쿼리 비용(10만 건 단일 측정만 있다), 시크릿 파일 마운트를 쓰는 컨테이너 기동.
- 요청별 만료 시간(RQ-039, ADR-0010): 롤링 배포 중 구·신 인스턴스 혼용과 롤백 실행, `MAILO_JOB_EXPIRY_MAX_SECONDS`를 기본 TTL보다 늘린 배치의 대기 건수와 점유 지연, 하한 60의 적정성.
- 발송 우선순위(RQ-038, ADR-0009): 롤링 배포 중 구·신 인스턴스 혼용과 롤백 실행, 대용량 테이블과 쓰기 부하 중의 `0005`(`CREATE INDEX CONCURRENTLY`) 적용 시간, 캐시가 차가운 상태의 점유 지연, 실제 다중 프로세스·장시간 부하에서의 등급 효과. 점유 쿼리 성능은 수동 측정이다(ADR-0009 구현 중 확정 3).
