# writing-styles

소스·테스트 주석과 `docs/` 문서를 쓰고 고치는 규칙이다. 새 주석·문서는 처음부터 이 규칙으로 쓴다. 기존 코드·문서에 일괄 적용하지 않고, 고치는 곳에서만 맞춘다.

한국어 작성, 결론 먼저, 금지 표현, 볼드체 사용 한도는 전역 지시가 소유한다. 여기서는 이 저장소에만 해당하는 규칙을 쓴다.

## 적용 대상

| 대상        | 위치                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------- |
| 소스 주석   | `apps/mailo/src`                                                                                              |
| 테스트 주석 | `apps/mailo/test`                                                                                             |
| 문서        | `docs/requirements`, `docs/adr`, `docs/operations`, `docs/api`, `docs/agents`, `AGENTS.md`, `CONTEXT-MAP.md`  |

`docs/`는 oxfmt 대상이 아니다(`.oxfmtrc.json`의 `ignorePatterns`). 표 열 정렬은 손으로 맞춘다.

## 문장 규칙

- 종결은 `~한다`체다. 목록 항목과 표 셀에서는 명사구 종결을 허용한다.
- 한 문장에 한 사실만 쓴다. 이유·결과·예외를 `~하므로`, `~해서`, `—`로 이어 붙인 문장은 나눈다.
- 나열·순서·조건 분기는 산문 대신 목록으로 쓴다.
- 확인한 사실만 쓴다. 코드를 읽지 않고 설명하지 않는다. 추정은 추정이라고, 확인하지 않은 것은 확인하지 않았다고 쓴다.
- 번역투와 어색한 조사는 자연스러운 한국어로 고친다.

나눔 예:

```text
전: lease가 만료되면 다음 claim이 작업을 회수하므로 drain 상한이 지나도 lease는 풀지 않는다.
후: drain 상한이 지나도 lease는 풀지 않는다.
    lease가 만료되면 다음 claim이 작업을 회수한다.
```

## 소스 주석

쓰는 것:

- 코드만으로 안 보이는 것: 이유, 불변식, 호출 순서, 부수 효과, 알려진 한계.
- 규칙의 출처: `RQ-NNN`, `ADR-NNNN 결정 N`. 문장 끝에 둔다.
- 모듈 `index.ts`가 공개하는 export는 한 줄 JSDoc 이상을 둔다. 동작을 첫 문장에 쓰고, 조건·이유는 문장을 나눠 잇는다.
- 수치 기본값이 추정이면 추정이라고 쓴다. 예: `/** RQ-008 기본값. 모두 추정이며 설정으로 바꾼다. */`

쓰지 않는 것:

- 이름을 되풀이하는 주석. 코드가 말하는 것.
- 요청 값(본문, 제목, 수신자, 자격 증명)을 예시로 넣은 주석.

형태:

- 한 줄이면 `/** ... */` 한 줄로 쓴다.
- 문장이 셋 이상이거나 분기가 있으면 목록으로 바꾼다.
- 선언 안의 지역 설명은 `//`로 쓴다. JSDoc은 선언에만 붙인다.
- 소스 주석에 `**→ 요지.**` 같은 대화용 표기를 넣지 않는다.

## 테스트 주석

- 파일 머리 또는 `describe` 앞 주석: 무엇을 고정하는지, 어떤 환경(PostgreSQL, fake SMTP, 파일 시스템)인지, 규칙이 사는 RQ·ADR.
- 상수를 일부러 import하지 않고 리터럴로 두면 이유를 쓴다. 값이 바뀌면 테스트가 실패하게 하려는 의도라는 점을 밝힌다.
- 주석만 고치는 커밋에서 테스트 제목을 바꾸지 않는다. 제목이 존재하지 않는 RQ·ADR을 가리키면 고친다.

## 참조 표기

허용:

| 표기                         | 뜻                                              |
| ---------------------------- | ----------------------------------------------- |
| `RQ-NNN`                     | `docs/requirements/mail-sending.md`의 요구사항  |
| `ADR-NNNN`, `ADR-NNNN 결정 N` | `docs/adr/`의 결정과 결정 번호                  |
| `ADR-NNNN 구현 중 확정 N`    | ADR의 날짜를 단 "구현 중 확정" 절 항목          |
| `docs/operations/<파일>.md`  | 운영 문서. 절 제목으로 가리킨다                 |
| `GitHub 이슈 #N`             | 이슈 트래커 항목                                |

금지(저장소에 남지 않는 곳을 가리킨다):

| 표기                                           | 대신                                          |
| ---------------------------------------------- | --------------------------------------------- |
| `_works/<작업>/…`, `.scratch/…`, `_tmp/…` 경로 | 지운다. 이슈면 이슈 번호로 가리킨다           |
| `DELTA-NN`·`LEG-NN`·finding ID                 | 지운다. 근거는 RQ·ADR·이슈 번호로 쓴다        |
| `docs/superpowers/…`, `.superpowers/…` 경로    | 지운다. 스킬 작업 문서는 저장소에 두지 않는다 |
| 없는 파일·절                                   | 지운다. 근거는 문장 안에 쓴다                 |
| "계획서에 따르면" 같은 사라진 문서 인용        | 근거 문장으로 바꾼다                          |

참조 문서·경로·ID는 존재를 확인한 뒤 쓴다. 문서 제목이나 절 제목을 바꾸면 저장소 전체 참조를 검색해 같이 고친다.

## 문서

`docs/requirements`, `docs/adr`, `docs/operations`는 현재 시점의 규칙·계약·근거를 담는다. 작업 이력이 아니다.

쓰는 것:

- 규칙, 계약, 불변식과 그 이유. 한 항목에 이유 하나.
- 규칙을 고정하는 테스트·스크립트의 파일 이름.
- 실측 근거는 사실 한 문장과 측정 환경(버전·조건).
- 운영 문서에서 확인하지 못한 것은 "검증하지 않은 것" 절에 적는다.

쓰지 않는 것:

| 쓰지 않는 것                                   | 대신                                          |
| ---------------------------------------------- | --------------------------------------------- |
| 소스 줄 번호·줄 수                             | 파일·함수 이름                                |
| 파일·테스트 개수                               | 이름 목록. 개수는 `testing.md`의 "결과 기록"이 정한 자리에만 쓴다 |
| "~를 더했다" 같은 작업 이력                    | 현재 동작. 이력은 git이 남긴다                |
| 결정 귀속("사용자가 정했다")                   | 지운다. 결정 기록은 ADR이다                   |

- 규칙·상수는 한 곳에만 쓰고 다른 곳은 문서와 절 제목으로 링크한다. 같은 규칙을 두 문서에 다시 쓰지 않는다.
- 날짜는 ADR 상태 절, "구현 중 확정" 절, 운영 문서의 대조·확인일, 요구사항의 검증 판정 근거에 쓴다.
- 진행 순서가 있는 절차는 번호 목록을 쓴다. 표 셀은 한 문장으로 쓴다.
- ADR 수정 범위는 `AGENTS.md`의 "문서와 요구사항 갱신"을 따른다.

## 고칠 때

1. 주석을 다시 쓰기 전에 대상 코드를 읽는다. 설명이 코드와 다르면 코드에 맞춰 고친다.
2. 틀린 설명을 찾으면 문체만 바꾸지 않고 내용을 바로잡고 커밋 메시지에 밝힌다.
3. 고친 수치는 다시 센다.
4. 문체만 바꾸는 커밋에서는 코드 동작을 바꾸지 않는다. 이름·로직 변경은 별도 커밋으로 나눈다.

## 검증

| 변경           | 확인                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------- |
| 문서만         | 금지 표기 검사. `pnpm format:check`는 `docs/`를 보지 않으므로 이 검사가 유일한 자동 확인이다      |
| 소스·테스트 주석 | `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`. 단계 기준은 `docs/agents/verification.md` |

금지 표기 검사는 이번에 고친 파일에만 적용하고 출력이 없어야 한다.

```bash
grep -nE "_works/|\.scratch/|docs/superpowers|\.superpowers|DELTA-[0-9]|LEG-[0-9]|F-R[0-9]" <고친 파일> | grep -vE "_works/(README\.md|templates/)"
```

추적하는 `_works/README.md`와 `_works/templates/`는 저장소에 남으므로 가리켜도 된다. workflow 절차를 정하는 문서는 작업 폴더와 작업 ID를 설명해야 하므로 검사 대상에서 뺀다. 이 문서, `workflow-shared.md`, `qq-workflow.md`, `rubber-workflow.md`, `verification.md`, `_works/` 아래 파일이 해당한다. 이 규칙 도입 전에 쓴 금지 표기가 남아 있을 수 있다. 고치지 않는 파일의 잔존은 검사 대상이 아니다.
