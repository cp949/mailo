# 계획

## 목적

- 독립 결과 하나를 한 문장으로 적는다.

## 변경 대상

- 예상 파일 경로와 변경 내용을 적는다.

## 확정 정책·계약

- 동작과 실패 조건을 적는다. 기존 계약을 유지하면 근거 파일과 RQ·ADR 결정 번호를 적는다.
- API 변경은 method/path, 요청 형식(JSON·JWS), 응답 타입, 인증(API 키·서명), problem+json 실패 조건, `docs/api/` 갱신 범위를 적는다.
- 스키마 변경은 대상 테이블·인덱스와 새 마이그레이션 파일(`apps/mailo/migrations/NNNN_이름.sql`), `-- mailo:no-transaction` 여부, 검증 범위를 적는다. 해당 없으면 `없음`으로 적는다.
- 환경 변수·로그 이벤트·레지스트리 필드를 바꾸면 갱신할 `docs/operations/` 문서를 적는다. 해당 없으면 `없음`으로 적는다.

## 완료 조건

- [ ] 독립 리뷰어가 구현과 검증 증거로 판정할 수 있는 조건을 적는다.
- [ ] RQ 진행 상태·수용 조건 체크 갱신이 필요하면 대상 RQ를 적는다. 필요 없으면 이 항목을 지운다.

## 최종 검증

구현과 리뷰 지적 처리를 모은 뒤 한 번 실행할 검증을 적는다. 선택 근거는 `docs/agents/verification.md`를 따른다. DELTA별 대상 검증은 각 DELTA 파일에 적는다.

- L0: 소스·테스트를 바꾸면 실행한다. 문서만 바꾸면 `실행 안 함`과 "문서만 바꾼 경우"의 점검 명령을 적는다.
- 통합: `apps/mailo/src`·`apps/mailo/migrations`를 바꾸면 L2 전체, 아니면 누적 대상 L1 또는 `없음`과 이유를 적는다. 누적은 DELTA의 "최종 검증 대상(누적)"에 쌓는다.
- L3: `verification.md` L3 표에 해당하는 스크립트. 해당 없으면 `없음`으로 적는다.
- 실행 담당자: 기본은 구현자다. 다르면 이름을 적는다. 기록은 `verification-log.md`에 남긴다.
- 실행하지 않는 검증과 이유.

## 범위 밖
