## 이전 finding 상태

- 첫 라운드는 `없음`으로 적는다. 재리뷰는 이전 ID별 처리 상태와 근거를 적는다.

## Standards: 지침 준수·결함 탐지

- 확인한 지침(`AGENTS.md`, `docs/agents/testing.md`, `docs/agents/writing-styles.md`)과 변경 범위를 적는다. finding은 아래에 기록한다.
- 시크릿 비노출(RQ-027): 로그·오류·이벤트·거부 기록에 요청 값이 들어가는 새 경로가 있는지 적는다.

## 처리

- finding ID별 수정 위치·검증 근거, 기각 근거 또는 GitHub 이슈 번호(등록 전이면 `pending-issues/`의 파일명)를 적는다.

## 검증

- 명령, 소스·env 지문, 종료 코드, 통과·실패 수, 로그 위치를 적는다. 구현자의 검증 기록을 인용한 것과 리뷰어가 직접 실행한 것을 구분한다.
- 기존 실패와 이번 변경의 실패를 구분한다. 실행하지 않은 검증은 `미실행`으로 적는다.

## 남은 위험

- 미검증 영역과 남은 위험을 적는다. 새 함정이 없으면 `새 함정 없음`으로 적는다.
